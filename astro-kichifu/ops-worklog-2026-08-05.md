## 1. 予約一覧を表組みにする

カード風の2段組みは項目の位置が行ごとに動いて読み取りづらかったため、列見出し付きの表に変更。
列は店長指定で **日付 / 時間 / お客様 / 電話 / キャスト / 分 / 場所 / 金額 / 状態**。

- コース名から分数を取り出して独立した列に（「イベント120分」→ 120分＋イベント）。コース名に分が無いものは開始〜終了から算出
- 電話番号は旧システムのデータに全角が混ざっているので半角へ揃えて表示（旧履歴は `c.phone` を SELECT に追加）
- 場所は自宅／その他の接頭辞を落とし、ホテルは市区町村を添える
- 数字は tabular-nums で桁を揃え、金額は右寄せ。狭い画面は横スクロール（段組みには畳まない）
- 旧履歴の行は開く先が無かったので、**予約編集ページと同じ見た目の読み取り専用モーダル**を新設。
  指名・交通費・部屋番号・店舗・メモまで確認できる
- `.bk-row` はマスタ一覧と共用のため、予約一覧は `.bkt-*` で独立させた

## 2. 出勤管理「10日先まで一覧」（新規タブ）

女性 × 10日のマス目。出勤は時間帯、休みは「休」、未定は「＋」、OPSのみは🔒。

- **マス目クリックでその場で編集**（状態＋時間）。保存経路は `$saveOne` / `$notifyShiftWebhooks` 共通なので媒体同期の挙動は他タブと同じ
- 出勤に切り替えたとき時間が空なら、同じ女性の他の日の時間を引き継ぐ
- 並び順の既定は「この10日の出勤が多い順」。
  **タブのリンクが sort を引き連れていて既定が上書きされていた**ため、タブ間では sort を持ち回さないようにした
- 見出しにその日の出勤人数、右端に女性ごとの出勤日数、本日の列を枠で強調

## 3. タイムラインの配色（目に優しい配色）

一日中見る画面なので、眩しさとにじみを減らす方向へ。`body[data-theme="soft"]` を既定にし、ヘッダーの 🌿 で従来配色へ戻せる（localStorage 保存）。

- 予約ブロックを「濃い塗り＋白文字」→「淡い地＋濃い同系色の文字＋左4pxの色帯」に反転

- ⚠️ `body[data-theme="soft"] .tl-staff` が `.tl-staff-unassigned` に勝って**未割当行のオレンジが消えていた**ので除外
- キャスト欄の区切り線（時間・件数・預り金・報酬・入金分）が金額側にしか引けていなかったので、
  擬似要素をセル幅いっぱいに伸ばして左端から右端まで通した（写真・名前・出勤ボタンはその上に重ねる）

## 4. 料金まわり

### ホテル料金（旧「初回ホテル特別料金」）
- 名称を **ホテル料金** に変更し、媒体チェックの直下へ移動
- `ops_courses.hotel_price` を追加し、**コース管理で持つ**方式に。チェックを入れるとコース料金欄がその金額に**置き換わる**（−5,500の割引行は出さない）。プルダウン表示・コース料金欄・合計が同じ金額で揃う
- 既存4コースには通常料金−5,500を初期値として投入（60分¥11,000 / 90分¥16,500 / 120分¥22,000 / 150分¥33,000）
- ホテル料金 未設定のコースだけ従来の一律−5,500のまま
- **本指名は対象外**（そのキャストとは2回目以降）。押せないようにし、チェックする前に条件が分かる注意を表示。
  先にチェックしてから本指名にした場合は自動で外れ、トーストで知らせる

### ＋10分（無料）
- 自動で入る条件は **LINE予約** または **当店が初めてのお客様の媒体経由**
- バッジではなく**チェックボックス**にして手で外せるように（媒体を見ていないお客様には付けない場合があるため）。
  手で触ったら以後は手の指定を優先
- 保存するコース名の末尾に「＋10分」を記録（例: `60分コース ＋10分`）。開くときは照合前に落とす
- コース管理に「＋10分のときのコース」を持たせ、設定してあればそのコースへ差し替える（分数・料金・報酬ごと）

### コースの組み合わせ（180分以上）
180分以上は単独コースが無く「90＋90」で運用するため、コースの下に2本目のプルダウンを追加。
分数・料金は合計。保存名は `90分コース ＋ 90分コース`。ホテル料金の引きは1回だけ。

### 指名料
**DBに1件も登録されておらず、全部0円で計算されていた。** 初1,100／本2,200／フリー0 を投入。

### その他
- 「出張費」の表記を **交通費** に統一（画面・コピー文面・経理の説明文まで20箇所）
- キャンペーン割引は YLKA 向けの仕組みなので、アドミでは新規予約に出さない（過去に割引が乗った予約を開いたときだけ外せるように表示）
- オプション欄の位置・媒体チェックのレイアウトを整理

## 5. 予約モーダルの操作性

- **自宅・オフィス** に切り替えると住所欄に市区町村を先に入れる。市区町村を変えたときも、住所が空か市区町村名だけなら追従
- **市区町村を選んでもホテル一覧が絞られない**ことがあった。「いつもの場所」の自動入力とエリアタブの同期で市区町村だけ変えていたのが原因。
  `populateHotelSelect()` を引数なしで呼ぶと現在の市区町村で絞るようにして再発も防いだ
- **休憩をステータスに統合**。独立したチェック行を廃止し、ステータスの選択肢に「💤 休憩・私用」を追加
- 見出しの担当・ステータスを本文の入力欄と同じ大きさに
- フッターの要約を店長指定の内容に。1段目=日付と開始時刻／2段目=金額の内訳を「名前 ¥金額」で／3段目=お客様と担当キャスト。合計は右端

## 9. ご利用回数をオーダー実データから数える

- `customers.php action=get` が `usage{legacy, ops}` をSQLで数えて返す。保存カウンタではなく実際のオーダーが正になり、履歴のLIMITにも左右されない
- **予約ステータスで1回と判断**。数える＝予約／事前予約／保留／接客中・接客完了。数えない＝問合せ／キャンセル／無連絡／休憩
- **キャンセルは「そのキャストとは会っていない」まま**（初指名の対象に残る）。
  旧履歴だけステータスを見ずに「会ったキャスト」へ入れていたため、キャンセル履歴があるだけで本指名扱いになっていた（1,784件が対象）
- 編集中の予約は自分の過去の利用として数えない（1回目なのに2回目と出ていた）
- ⚠️ `bookings.php` が保存・完了・接客開始で `visit_count` を +1 していた。「未」に戻して「始」にし直すたびに増える（実例: 1件の予約で3回）。
  この列は**旧システムの実績専用**なので加算を3箇所とも撤去。ズレていた顧客を再計算（404件）

## 11. セキュリティ・同時編集

### 予約の同時編集（併用方式）
- **編集ロック**（`ops_booking_locks`）: 予約編集モーダルを開くとロックを立て、別端末は
  「⚠️ ◯◯さんが編集中です（読み取り専用）」で保存・削除を無効化。30秒ごとに延長、90秒で自動失効。
  閉じる／保存で解放し、ページ離脱時も sendBeacon で即返す
- **保存時の追い越しチェック**（楽観ロック）: 開いた時点の `updated_at` を添えて保存し、
  その間に別端末が保存していたら 409「他の端末で更新されています」で止める。タイムラインの時刻変更・始/終にも適用

### 信頼済み端末ログイン
毎回のログインを無くしつつ、パスワードだけの守りから脱する。

- 初回の端末: パスワード ＋ メールの6桁コード ＋ **端末の名前** で登録
- 登録済みの端末: セッションが切れても Cookie から黙って復帰（操作なし）。有効期限90日・使うたび延長
- ログアウトはその端末の自動復帰だけ止める（登録は残す）。次はパスワードだけで入り直せる
  ＝ログアウトが自動復帰に打ち消されない
- **端末とログイン画面**（`ctrl/devices.php`）: 送り先メールの設定、端末一覧、名前変更、解除（紛失時の遠隔ログアウト）、この端末以外を一括解除
- DB: `admins.email` / `admin_trusted_devices`（token_hash・device_name・expires_at・auto_disabled_at・last_ip・user_agent）

> ⚠️ **未了**: 認証コードの送り先メールアドレスが未設定。`https://admi2888.com/ctrl/devices.php` で設定し、
> 一度ログアウトして端末登録まで通す（メールが届くかの確認も兼ねる）。
> 送信元は `no-reply@admi2888.com`。Gmail宛が迷惑メールに入る場合は SPF/DKIM の調整が必要。
